# Frozen benchmark design · exact TIE evaluator

**Target.** Preserve the published TIE policy of the previous project run, including its exact-immediate incumbent and arrival-lexicographic secondary tie rule. Optimize only computation. At most four ready requests, fixed prefix-leaf LRU at 128 or 32 complete 512-token blocks, one-second gate, warm-up, chronological history and two-cohort/eight-pair integer objective follow the parent freeze. The method and counterexamples are derived in [derivation.md](derivation.md). Every tested bin is exposed. This is an equivalence and machine-performance comparison.

**Treatments.** One native binary and compiler setting implement K (k-LPM), IMM (exact least immediate work with legacy incumbent priority), REF (historical tie-only, exact per-full-state rollout) and OPT (same tie-only decisions, history-pair equivalence and certified direct scoring). Native code computes its own incumbent once. K and IMM receive only the current group in the timed session. They have no historical maintenance charge. REF and OPT have the same maximum historical demand and same causal update boundary. All receive the same numeric input preparation, C++ transition representation and response interface, including the entire resulting MRU tuple. Process history, cache and memo state reset between episodes. No timing-based development choices or scientific policy revisions.

**Correctness before timing.** Run small-state and fixed regression tests, comparing actual order, incumbent tie rule, complete exit, integer cost and absolute objective against reference computations. At freeze pin source, binary, tests, runner and inputs. In one integrated run, first replay each of the two old integration bins and all 56 bins with published tie-only outcomes at both capacities. Check REF and OPT in absolute-score mode, every selected order against the archived dispatch and independently reconstructed complete timestamp/leaf-LRU state. Compute the reference selected action's absolute continuation cost directly by the parent simulator on the historical pairs. Verify both native objectives, immediate blocks, and episode totals. Include K and IMM against their recorded orders and reconstructed states. No new public data. Any post-freeze mismatch invalidates the affected claim; stop and retain the record.

**Matched timing.** Use only the 56 bins of the previous report's primary workload for timing and prefill totals. Three fixed repetitions per traffic/capacity/method. Within each repetition the four traffic/capacity combinations and four method orders are shuffled by one fixed PRNG seed (20261108). For each cell use a fresh native process, reset before each bin, issue warm-up groups and then serve every measured group in chronological order. Decision mode may omit computing an additive objective constant when the action is already determined. Verify each timed trajectory against the absolute-score run. No evaluation-derived memo tables are carried across runs. Cache-neutral Python input preparation (trace parsing, cohort gating and canonical IDs) is shared and metered separately. Charge history-dependent state construction and updates to the respective method.

**Measurements.** Record native selection CPU, ingestion/preparation CPU and live-state/history update CPU where measurable. Measure caller wall and caller CPU from sending a current group through receiving its decoded result. Child process CPU and outer wrapper CPU include timers, parsing, formatting, resets, warm-up and instrumentation. Report mean, p95, p99 and maximum, timings for each traffic/capacity, total native and end-to-end costs, candidate/simulation/memo counters and peak RSS. Keep end-to-end IPC/JSON response costs visible; the reported state/diagnostics are an audit interface. Separate verification from the decision-only timing. Compare OPT vs REF for evaluator speedup and OPT vs the native IMM and K as practical controls. Report all repetitions and avoid population intervals from timings. Conditional prefill is checked identically per method and reported once. Never subtract scheduler time from positions.

**Resources.** CPU-only local execution. One single-threaded child active per replay stream. Protect the one-core-hour numerical subcap with a wall guard for two sequentially interacting single-thread processes, allowing for prior tests, compilation, and reporting. Four cumulative active-work hours, eight charged core-hours and original expiry apply. Preserve outputs if a frozen check fails. One integration; no autotuning, additional predictors, or timing retries.
