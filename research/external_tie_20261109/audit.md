# Independent external validation audit

## Pre-evaluation review

All 13 source, binary, test and receipt hashes in the archived exact-evaluator freeze match their on-disk artifacts, including the underlying prefix LRU transition. The prior 8,766 decision comparisons support implementation equivalence on exposed traffic. The historical argument preserves adaptive k-LPM costs only when the projection retains relevant identities and *absolute* ranks, and the direct-score test is sufficient only when union size plus leading outsider count fits. None of these claims guarantees lower *episode* prefill. In the older study the 128-block tool workload produced the savings, at 3.19× faster native scheduler CPU than reference and approximately 9.45× the CPU of immediate ordering. Conversation saved zero prefill positions.

For the external comparison, the relevant reproducibility checks are independent per-workload namespace, cumulative exact prefix IDs, complete blocks before the mandatory final token, inclusion of all eligible requests, causal warm-up/history and one continuous measured trajectory per policy. A domain-remapped isolated 16-token block alone cannot identify a prefix. The source supplies no tenant identifier; session or known parent lineage can support conservative namespace isolation, while released file identity alone cannot establish shared tenancy. Control comparisons need identical admission gates, tails, cache transitions, chronological demand and result interfaces. Randomization is over unique complete eligible exits; per-order draws would give a different distribution. The simple frequency control counts *occurrences* in the preceding completed cohorts; future cohorts and label-dependent statistics cannot enter. Displacement is within the cohort. The prior gate includes a request arriving exactly at its deadline.

Timing repetitions share traffic and indicate hardware variability only. Chronological windows share recurrent states and cannot supply independent-system sampling error. Any serialized break-even is local incremental decision wall time divided by positive saved positions, with collection delay canceling only against the identical gate. Time to generate trace-derived paths and peak RSS should be distinguished from per-decision wall time, native scheduler CPU, and historical membership-index bytes.

This review performed no new policy replay, external download, or budget/lock mutation.

## Implemented design reviewed before external outcomes

The protocol fixes the earliest 21,000 rows, including 1,000 FCFS warm-up requests, a separately gated uninterrupted 20,000-request analysis episode, four diagnostic windows and two timing repetitions. The chronological adapter checks raw file digests, positive lengths, exact source block counts and time order. Repeated edge hashes are interned by equality of the complete (parent identity, edge) pair. The source 16-block tuple is complete before construction of a 512-token edge, and both representations cap the reusable path at floor((input_length−1)/block_size). Paths are scoped to separate roots for each file and causally observed session ancestry. The domain remapper may already have merged truly distinct content via a source-hash collision; equality proves identity of released symbols only. Offline canonicalization uses a one-pass online map. The native process re-interns only IDs seen when a cohort arrives and receives neither future file records nor the mapping table.

The B adapter receipt classifies all 21,000 requests as unrelated roots. Consequently every B request has a disjoint prefix identity namespace. All policies must have exactly the input token sum in measured B prefill. B can still supply a timing comparison, but this episode cannot test sharing of system prompts across unlinked clients. The A receipt classifies 8,589 requests as having a known prior parent and 12,411 as roots. These counts were available solely from the adapter and before external policy effects.

I inspected the C++ matched-interface source and its build transformation. It imports digest-locked parent implementation and transition source; the only scientific compile-time difference for native resolution is the 4,096-element state extent. The original-size binary is used at coarse resolution. k-LPM, exact immediate, OPT and the bounded integration reference invoke frozen selection logic. FCFS applies the common transition in arrival order. RAND uses a fixed-seed 64-bit rejection draw on unique immediate-minimum full-state representatives. RANK counts one occurrence per node per request in the same complete historical pairs, computes the prescribed linear-rank score in 64-bit arithmetic, then uses incumbent and lexicographic priority. In the measured phase the 16-cohort historical window is already full. Commits occur after the dispatch. All policies pay for common per-current-cohort parent-identity verification; RANK/OPT pay for their own index and history maintenance. The integration mode compares reference and optimized absolute scores as well as decision-only optimized order, incumbent, cost and complete exit. No reference timings enter the practical break-even analysis.
