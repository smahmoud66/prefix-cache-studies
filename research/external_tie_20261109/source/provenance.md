# Qwen/Bailian data and adapter

The Git revision was resolved and source documentation and both Git LFS pointers were inspected before acquiring either evaluation object. The two published full data files total 152,564,475 bytes. Local SHA-256 digests equal the authors’ LFS object IDs. Full object sizes, record counts, timestamps, schema and checksums are in [source_metadata.json](source_metadata.json). The source distribution carries the [Apache 2.0 notice](LICENSE.meta). The inspected README and Q&A are preserved locally. Repository link inspection and the pinned copy of the README refer to the same underlying work. No keyword web searches or other datasets were used. [Authors’ pinned release](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/tree/5f7439c51ec248a0c585f7d90a41a6f57773b912)

**Source facts.** These are two sampled two-hour streams from a Qwen serving cluster on Aliyun Bailian. A is the chat stream and B is API automation. Relative arrival timestamps are seconds, input and output lengths are in token positions, and the source provides a chat identifier, parent chat identifier, turn, request type and the ordered block IDs. The authors applied salted SipHash-2-4 to individual 16-token blocks and remapped the resulting hashes to integers. Model templating has already occurred. The authors describe padded final blocks and changes to special tokens between turns. No future output tokens were reconstructed. [README](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/blob/5f7439c51ec248a0c585f7d90a41a6f57773b912/README.md) · [Authors’ Q&A](https://github.com/alibaba-edu/qwen-bailian-usagetraces-anon/blob/5f7439c51ec248a0c585f7d90a41a6f57773b912/docs/qa-context-growth-pattern.md)

**Project exposure.** A case-insensitive search of previous research and eight-round records for Bailian and the two trace filename stems found the word Bailian in a query reservation in [the commitment study’s source log](../../commitment_20261108/token_sources.md). That log identifies Mooncake as the traffic actually downloaded. The preceding tie study's benchmark freeze identifies those Mooncake bins. No historical Qwen/Bailian replay, result, data file or policy exposure was located in the project. This finding is limited to the available records. The chat/API choice came from the study request.

**Replay assumptions.** Numeric identities are local to a file and representation. The modeled cache is shared in size across one stream, with prefix matches allowed only within one declared logical chat lineage. A first-seen chat with root parent starts a private namespace. A first-seen chat inherits the namespace of an already observed parent. A missing parent starts an isolated namespace. A repeated chat uses its recorded namespace and a conflicting known parent is rejected. The adapter never merges earlier histories retroactively. Actual identities and salts cannot be independently resolved from the release. This conservative scope does not identify tenant membership, production cache isolation, physical placement or a shared namespace between files. Request types describe modalities and do not establish a tenant. Routing, concurrency, dispatch and service completion are unobserved. Rows with identical timestamps preserve source file order.

**Observed structure.** In the first 21,000 rows of A, all 8,589 nonroot parent links point to earlier chats, and 12,411 chats are roots. B contains 21,000 root requests. Every chat ID is unique in each selected stream. B can have no cross-request prefix reuse under the lineage restriction. It is therefore informative about overhead in that isolation regime and uninformative about sharing between API clients or independent sessions. These checks examined only identifier and timing metadata before any policy effects. Row-1,000, row-1,001 and row-21,000 timestamps appear in the metadata inventory.

**Derived representation.** Within each lineage, the adapter interns (preceding canonical node, exact incoming edge). For native resolution, an edge is a source ID. For the 512-token condition, it is an ordered tuple of 32 source IDs. Python dictionary keys are compared in full even if internal hashes collide. Released source hash collisions cannot be detected. The resulting dense positive IDs name complete cumulative prefixes. Different parent prefixes cannot merge by sharing one isolated block. For length L and block size b, the row exposes at most min(floor((L−1)/b), 65,536/b) nodes from the beginning. Original L is preserved for the compulsory suffix. Source rows have exactly ceil(L/16) identifiers throughout both files. Incomplete blocks and the complete aligned block containing a mandatory final token never receive reuse credit. For a smaller capacity, the common engine truncates the path further. Policy input rows contain only timestamp, original input length and these node identities. [Adapter and hand fixtures](../adapter.py)

**Reproduction.** The full files are already present. For reconstruction in an empty source directory use the pinned media URL below, then check against the two LFS digests before converting. From the study directory:

```sh
rev=5f7439c51ec248a0c585f7d90a41a6f57773b912
for label in A B; do
  file="qwen_trace${label}_blksz_16.jsonl"
  curl -fLsS --max-filesize 100000000 "https://media.githubusercontent.com/media/alibaba-edu/qwen-bailian-usagetraces-anon/$rev/$file" -o "source/$file"
done
python3 source_metadata.py
python3 adapter.py fixture
python3 adapter.py A --rows 21000
python3 adapter.py B --rows 21000
```

Panel files use exclusive creation to preserve the archived panel on rerun. Metadata plus license and full trace file payloads saved during acquisition totaled 152,583,848 bytes. This excludes service-managed web retrieval, GitHub API metadata and HTTP overhead, which were not metered. The initial Git LFS downloads were individually capped at 100 MB and metadata-file fetches at 64 KiB. The objective used none of the authors’ accuracy, serving latency or cache-performance estimates.
