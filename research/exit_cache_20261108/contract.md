# Causal value of the exit cache · prospective research contract

**Question.** In Mooncake conversation and tool/agent trace replay, can ordering the same ready requests using two cohorts of estimated continuation cost reduce complete-episode prompt prefill versus exact immediate ordering, with ordinary LRU fixed? A current reorder can change which prefixes or recency ranks survive the next admission. A useful prediction would save more later than it costs now. The opposite outcome is plausible: serving recent demand again can protect prefixes whose last real use has passed.

**One method.** Keep 512-token blocks, mandatory final-token computation, capped contiguous prefix retention, separate transient workspace, fixed time bins, FCFS/LRU warm start, the four-arrival/one-second gate and movement within a cohort only. At each decision take the last at most 16 *completed* chronological cohorts before the current one, dropping the oldest leftover singleton. Pair them from the newest end, preserving forward order in each pair. Each pair starts at the same candidate exit with a fresh simulated clock. Continuation uses k-LPM/LRU with k=2, resetting its cycle in each cohort. Weight every pair equally. Compute the immediate and continuation work for every legal order of the current cohort. Minimize immediate work plus the mean of these two-cohort continuations. Arithmetic uses integer missing full blocks and multiplies immediate work by the number of pairs. All other positions in those fixed requests add the same constant for every alternative. An empty history returns the historical exact-immediate/LRU incumbent. If the incumbent ties for minimum objective retain it, otherwise take the arrival-lexicographically first minimizer. No tuned coefficient, recency window search or estimator refinement. The one-step control uses the first cohort of each identical pair. The tie-only control applies the two-step objective exclusively to actions with minimum immediate cost.

The warm-up cache sees the historical FCFS access order. Group those same requests in arrival order using the original gate (flush at the warm-up boundary); completed warm-up cohorts are available to each history. Measured cohorts start afresh at the same boundary as in the original replay. Histories update in arrival order after commitment, independent of each method's chosen order. No cross-bin learning. Every policy sees the same current/past information and maintains its own cache. All trial states are private copies. Cache hierarchy is an immutable function of the observed chained IDs. On C++ calls the only input data are the entry MRU order, current prefix paths and completed history; the supplied immediate incumbent is calculated by the pinned original simulator from the same observable state.

**Exact reductions.** Between admissions, canonicalize full LRU state by retained identities in most-recent-first eviction order (reverse of the deterministic victim order); reachable equal stamps belong to a single path. On access, prepend the retained portion of the current path shallow-to-deep, remove its prior occurrences, and truncate at capacity. For every evictable subtree a descendant is at least as old as its ancestor, with deeper nodes evicted first on equal stamps. Therefore truncation leaves a valid trie and reproduces the original protected-path leaf eviction. Equal canonical tuples admit the same hit prefix and next tuple on any common request; induction gives identical simulated continuation work. Among actions with equal full exit tuples, the minimum immediate-cost representative dominates, retaining incumbent/lexicographic tie priority. Equal resident *sets* can yield different costs: at capacity two, MRU orders (a,b) and (b,a) incur respectively one and two misses on c,a. A hand case with historical singleton cohorts [a/x],[a/z], initial a/z and current [b/t,a/x] has immediate options costing three and four blocks. Their historical continuations cost three and one. The two-step objective permits paying four now. This establishes possibility under model assumptions. Recent cohorts' predictive value for actual successors is an empirical uncertainty. The previous immediate certificate cannot settle that comparison. [Independent review](review.md)

**Related work and distinction.** TOPAS already scores post-decision states, PEEK exploits queued reuse, and learned eviction predicts continuation. The scoped contribution here is the measured effect and overhead of changing only order under fixed LRU using anonymous prefix histories; neither generic value scoring nor predictive caching is a novelty claim. Inspected source versions, assumptions, objections and coverage are in [sources.md](sources.md). An exact duplicate with no unresolved scientific comparison would block this run. Implementing full historical clocks beyond the complete future-equivalent MRU tuple is unnecessary; using resident sets alone would invalidate the estimator. These are bounded implementation issues. The strength of temporal persistence and stability between traces remain measured uncertainties.

**Population and primary outcome.** Census of the previously unused 28 bins in each of two public sampled one-hour traces, conditional on the recorded prior exposure. All earlier 40 used bins are development evidence. [split.json](split.json) freezes the literal IDs, parent hashes, inputs and exposure reasoning. Unit is a time bin. At 128 blocks compare exact-immediate/LRU positions minus proposed/LRU positions per measured request within each bin (zero for an empty bin), then weight bins equally within trace and traces equally. Positive favors the proposal. Report the exact census mean, each trace, paired bin sign counts and spread, largest gains/losses and concentration. No sampling interval for this census or unsupported extrapolation to independent future traffic. Secondary capacity 32. Include FCFS/LRU, k-LPM/LRU, historical queue-aware portfolio, two-step proposal, one-step control, tie-only ablation and exact immediate/LRU. Give comparisons with k-LPM and the other strong controls. For each capacity report immediate sacrifice and total contrasts distinctly, selection from identical-residency/different-recency states, distinct exits, complete prefill, waiting/displacement and CPU costs.

**Privileged diagnostic.** Only after all online dispatch records are sealed, analyze the proposed policy's entry states for (i) all deviations from its same-entry immediate incumbent and (ii) a deterministic 1/16 sample of other decisions: SHA256 of UTF-8 'trace/bin/capacity/zero_based_cohort', first eight hex digits modulo 16 equals zero. Require two following cohorts in the same measured episode; report truncated coverage. Enumerate current orders, then serve the real next two cohorts from each exit by k-LPM/LRU. Compare chosen vs incumbent and vs minimum total current+two-cohort work, including ties. Report changed and sampled unchanged strata separately. These overlapping costs are diagnostic, never cumulative savings. Compute the parent offline interval bound only after sealing, as a ceiling on possible savings.

**Cost and stopping.** Single-thread coordinator replay and sequential single-thread native evaluation subprocess; at most two numerical processes. Maximum numerical allocation 3,600 CPU-seconds incl development/diagnostic; maximum local charge 28,800 seconds and four active-work hours, original expiry November 16 at 14:33:50 UTC. Include child and wrapper timing, mean/p95/p99/max decision overhead, state simulations, predictors, input preparation and memory limits. Exact held-out effects are opened only after a freeze receipt. Preserve all finished bins and failure records on cap or interruption. Any scientific defect after evaluation invalidates affected comparisons. No scientific revision after evaluation. A positive disposition requires an interpretable complete-episode benefit against strong LRU controls considering concentration and overhead. A marginal or trace-dependent result is mixed; a valid comparison with no advantage supports the corresponding scoped negative disposition.

**Instrumentation and exposure.** The two integration bins were conversation 7 and tool/agent 3, both previously exposed. Each baseline produced its original orders and costs at both capacities. Before the evaluation freeze we added flags comparing the chosen exit to the same-entry incumbent by resident set and complete LRU order; these flags only record comparisons. Engine timing excludes parsing its incoming line and serializing the reply, which are included in whole-process CPU and end-to-end wall timing. We charge the wrapper's computation of the immediate incumbent to each history-based method. No development result was used to change H, M, thresholds, cohorts, controls or trace allocation.

**Complexity.** Let K≤4, A=K!, C the retained block capacity, U≤A distinct full exits and m≤8. Shared-prefix enumeration of orders makes at most sum from j=1..K of K!/(K−j)! transitions. Each native update scans O(C) nodes. State grouping in ordered containers can cost O(A C log A + U C(log C+log U)) including resident-set diagnostics. A scored representative adds at most m H K continuation transitions. Choosing the next request by k-LPM uses O(C+K log(C+1)) for marking and prefix-hit lookups. Scoring workspace includes O(A C) candidate vectors and O(m H K C) input history plus the parent incumbent and its scratch space. Scores compare exact integers in block units, including immediate work. Production scheduling time would also include actual KV interactions and concurrency.
